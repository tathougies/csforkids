\week{Data everywhere}

As we have seen in the last few weeks, computers follow rules. But what do they actually think
about?  The surprising answer: everything -- words, pictures, even sounds -- is just
numbers. Computers use numbers to represent and reason about data. \curious{And those numbers?
  They’re built from the same tiny on/off switches we used before. So even words are secretly made
  of bits.}  In a sense, programs like Python are really just very fancy calculators.

Everything on a computer is stored as numbers. Even the words we saw last class are stored using
numbers. Every letter in a word (what Python calls a string) is assigned a number. We call these
numbers the \term{encoding} of the string.\hint{Python will sometimes abbreviate \term{string} as
  \code{str}.}

Most modern computers today use the \term{Unicode} standard for encoding strings. Unicode is a
\emph{huge} dictionary mapping every character humans have written to a number assigned by an
international committee.\didyouknow{As of the latest Unicode standard, there are over 297,334
  characters -- including ancient scripts, math symbols, and even musical notation. That's a lot of
  letters!\\
  You can check out all 290,000 characters on
  \resource[qrcode, text={the Unicode website}, description={Browse all the Unicode characters},
    kind={Resources}]{https://home.unicode.org/}} Before Unicode standardized the mapping of characters, computer systems would often use
their own custom standard or a standard particular to individual countries and languages. Reading
files created using one standard on a computer designed to work with another standard could result
in garbage data. Another common way to write strings as numbers is called \term{ASCII}, which stands
for the \emph{American Standard Code for Information Interchange}. ASCII covers most characters used
in English and related languages. It's also compatible with Unicode -- Unicode includes ASCII as a
subset, so the same numbers are used for basic English letters.

It sounds strange at first: letters becoming numbers. But once you see it, you can’t unsee it. Try
this in Python:

So far, we have mostly worked with one thing at a time: one number, one word, one answer. But real
programs often need to keep track of many things at once. A shopping list, a high score table, the
names of players in a game -- these are all \term{lists}.

As the name suggests, \term{lists} keep track of many numbers or strings. You can write a list using
\code{[} and \code{]}.

\begin{replbox}
>>> [1,2,3]<ENTER>
[1, 2, 3]
>>> ['my name is', ' travis']<ENTER>
['my name is ', 'travis']
\end{replbox}

Lists can contain both strings and numbers.

\begin{replbox}
>>> [1,2,'hello']<ENTER>
[1, 2, 'hello']
\end{replbox}

We can look up a particular value in the list by using \code{[} and \code{]} again!

\curious{Computer scientists usually start counting at zero. One
  reason is that computers naturally measure positions as ``how far from the beginning,'' and the
  first thing is zero steps away.}
\tikzforeground{
  \CheckTikzPictureSide
  \node[anchor=west] (index note) at ([yshift=-1em, xshift=10em]index) {
    \begin{tcolorbox}[code note, width=4cm]

    \end{tcolorbox}

>>> [1,2,'hello'][(*@\tikzmarknode{index}{}@*)2]<ENTER>
'hello'
>>> [1,2,'hello'][1]<ENTER>

All the items in a list are numbered with a special number called an \term{index}. The first item in
the list is at index \code{0}. The subsequent item is at \code{1}, the next at \code{2}, and so
forth.

\curious{Unlike many programming languages, Python also allows you to use \emph{negative}
  indices. Index \code{-1} refers to the last element of the list, \code{-2} to the element before
  the last element, etc. This can get confusing, so we like to stick with non-negative numbers. But,
  it's a fun party trick.}
If you try to access an element with an index that is larger than any item in the list, you'll get
an error.

\begin{replbox}
>>> ['word1', 'word2', 'word3'][4]<ENTER>
IndexError: list index out of range
\end{replbox}

Writing out our lists every time we want to talk about them can be really complicated. It's much
easier to give large lists a name, and then use them later on. We can name things using \code{=}.

\hint{Remember that the double equals sign \code{==} checks if two things are equal, but \code{=}
  assigns a name to a piece of data.}
\begin{replbox}
>>> a = ['bob', 'alice', 'mary', 'joseph', 'benjamin', 'tony']<ENTER>
>>> a[3]
'joseph'
\end{replbox}

In the example above the name \code{a} was assigned to represent the list with six names. After we
assign the name, then we can use \code{a} instead of typing out the entire list.

\subsection{Changing Data}

One of the nice things about naming things is that we can change them. You can change a particular
item in a list like this:

\begin{replbox}
>>> a = ['bob', 'alice', 'mary', 'joseph', 'benjamin', 'tony']<ENTER>

>>> a[3] = 'tom'<ENTER>

['bob', 'alice', 'mary', 'tom', 'benjamin', 'tony']
\end{replbox}

You can also \emph{add} elements to a list using \code{append}.

\begin{replbox}
>>> a = ['bob', 'alice', 'mary', 'joseph', 'benjamin', 'tony']<ENTER>
>>> a.append('sam')<ENTER>
>>> a
['bob', 'alice', 'mary', 'joseph', 'benjamin', 'tony', 'sam']
\end{replbox}

And finally, you can remove things from lists using \kw{del}.
\begin{replbox}
>>> a = ['bob', 'alice', 'mary', 'joseph', 'benjamin', 'tony']<ENTER>

\subsection{A Curious Case}

\curious{Whenever order matters, a list is often a good model. A recipe, a to-do list, and the moves in a dance can all be stored as lists.}
Try the following:

\begin{replbox}
>>> a = ['bob', 'alice', 'mary', 'joseph', 'benjamin', 'tony']<ENTER>
>>> a<ENTER>
['bob', 'alice', 'mary', 'joseph', 'benjamin', 'tony']
>>> b = ['bob', 'alice', 'mary', 'joseph', 'benjamin', 'tony']<ENTER>
>>> b<ENTER>
['bob', 'alice', 'mary', 'joseph', 'benjamin', 'tony']
>>> a[3] = b
>>> a
['bob', 'alice', 'mary', ['bob', 'alice', 'mary', 'joseph', 'benjamin', 'tony'], 'benjamin', 'tony']
\end{replbox}

In Python, lists can contain lists! Wow!

Now for something strange. At first this may look impossible -- but it reveals something important
about how Python represents complex data. Remember how we said we can use the name instead of
writing out the list. In the above example, \code{a} and \code{b} were the same list. That means we
should be able to use \code{a} in place of \code{b}.

\begin{replbox}
>>> a = ['bob', 'alice', 'mary', 'joseph', 'benjamin', 'tony']<ENTER>
>>> a<ENTER>
['bob', 'alice', 'mary', 'joseph', 'benjamin', 'tony']
>>> a[3] = a
>>> a
['bob', 'alice', 'mary', [...], 'benjamin', 'tony']
>>> a[3]
['bob', 'alice', 'mary', [...], 'benjamin', 'tony']
>>> a[3][3]
['bob', 'alice', 'mary', [...], 'benjamin', 'tony']
\end{replbox}

It seems as if \code{a} is somehow different from \code{b}. You may now be questioning whether you
were lied to about names being interchangeable with the data they represent.

This again goes back to the lesson from week 2 where we created drawings of ducks on the
computer. Being able to draw a duck from a description is not the same as a real duck. Computers
model things, and this is exactly the same case.

In reality, computer names cannot store anything. As we said at the beginning of this chapter,
everything on a computer is a number. Inside Python, Python variables really only store
numbers. That means, if we want to put a list into them, we first have to represent the list using a
number.

But there's a problem. Depending on what kind of computer you are using, Python can only store
numbers with 32 or 64 binary digits. On a 32-bit computer, names are limited to storing numbers
between 0 and 4 billion. There are \emph{much} more than four billion possible lists!

A Python variable does not magically hold an entire giant list inside a tiny box. Instead, Python
gives the list an internal number and uses that number to keep track of where the real list is. We
can see what number Python has chosen to associate with this list using \code{id}.

\begin{replbox}
>>> a = ['bob', 'alice', 'mary', 'joseph', 'benjamin', 'tony']<ENTER>
>>> id(a)<ENTER>
139920520053504
>>> b = ['bob', 'alice', 'mary', 'joseph', 'benjamin', 'tony']<ENTER>
>>> id(b)<ENTER>
139920522242624
\end{replbox}

Notice that whenever you create a new list using \code{[} and \code{]}, the \code{id} for the name
changes. This is because Python has arbitrarily decided to use this number for \emph{that}
particular list. \didyouknow{You could theoretically go from an \code{id} to the Python list
  directly. This is considered dangerous though, because you don't know which numbers Python has
  allocated for what sort of thing. If Python let you ask it to interpret any number as a list, you
  might end up asking it to do the impossible! Some languages, like C or C++ allow you to do this,
  but they are considered \emph{unsafe} languages, because you could crash your computer. But don't
  worry, you cannot crash your computer with Python! It's a very safe language!} If you were to
restart Python or Thonny, these numbers might change. But it doesn't matter for us, because as long
as we're working within Python, Python automatically translates these numbers for us.

Now perhaps, we can understand what happened above. When we assigned \code{a[3] = a}, we were really
storing the \code{id} of \code{a} into the fourth element of \code{a}. When we later went to access
\code{a[3]}, Python looked at the number, determined it was actually representing a list, and went
to look up that list, which happened to be \code{a}. When Python notices its going in a loop, it
sometimes writes \code{[...]} instead of the full list.

When we instead assigned \code{a[3] = b}, then Python allocated a \emph{new} number for
\code{b}. Then, when asked to print \code{a}, when it came to \code{a[3]}, it again saw it was a
list, but this time it was the list represented by \code{b}. \code{b[3]} was never changed, because
\code{b} does not have the same \code{id} as \code{a}. \prettyref{fig:pointers} demonstrates exactly
what is happening with \code{a} and \code{b}.

\begin{BigIdeaBox}
  A variable name is not the data itself. It is a way for Python to keep track of the data. This is
  why two names can sometimes refer to the same underlying object. It all depends on which number
  Python has assigned to it.
\end{BigIdeaBox}

    names, with different \code{id}s, as shown in subfigure (a). When you assign a list to an item

\section{Dictionaries}

\curious{Or really, zeroth, first, second, and third...!}  Lists are great when we want to look
things up by position: first, second, third. But sometimes position is not what we care about. If we
want to know Bob’s age, it is much nicer to ask for \code{'bob'} than to remember that Bob happened
to be item number 3 in some list. Dictionaries let us do exactly that

For example, we can store the ages of our friends like this:

\tikzforeground{
  \node[anchor=west] (key note) at ([yshift=-1em, xshift=8em]key) {
    \begin{tcolorbox}[code note, width=8cm]
      The labels in a dictionary are called \term{keys}. They play a role similar to list indices, except that keys do not have to be numbers.
    \end{tcolorbox}
  };
  \draw[->] (key note.west) to[out=180,in=-90] ([xshift=2em, yshift=0.8em]key.south);
}
\begin{replbox}
>>> ages = { 'bob': 8, 'sam': 6, 'amy': 9 }<ENTER>
>>> ages[(*@\tikzmarknode{key}{}@*)'bob']<ENTER>
8
\end{replbox}

Similar to lists, we can update existing keys:

\didyouknow{Under the hood, dictionaries are stored as special kinds of lists, which are themselves
  stored as numbers. It's numbers all the way down!}
\begin{replbox}
>>> ages = { 'bob': 8, 'sam': 6, 'amy': 9 }<ENTER>
>>> ages['bob']<ENTER>
8
>>> ages['bob'] = 9<ENTER>
>>> ages
{'bob': 9, 'sam': 6, 'amy': 9}<ENTER>
\end{replbox}

You can also delete keys using \kw{del}.

\begin{replbox}
>>> ages = { 'bob': 8, 'sam': 6, 'amy': 9 }<ENTER>
>>> del ages['bob']
>>> ages
{'sam': 6, 'amy': 9}<ENTER>
\end{replbox}

Unlike lists, assigning to a new key is not an error. Python simply creates that key for you.

\curious{A list answers the question ``what is in slot number 3?'' A dictionary answers the question ``what value goes with this name?''}
\begin{replbox}
>>> ages = { 'bob': 8, 'sam': 6, 'amy': 9 }<ENTER>
>>> ages['tom'] = 3
>>> ages
{'tom': 3, 'bob': 8, 'sam': 6, 'amy': 9}<ENTER>
\end{replbox}

But looking up a missing key is different. In that case, Python raises a \kw{KeyError}, because it cannot find the label you asked for.

\begin{replbox}
>>> ages = { 'bob': 8, 'sam': 6, 'amy': 9 }<ENTER>
>>> ages['beth']
KeyError: 'beth'
\end{replbox}

Let's walk through it. The \code{say} function tells the story to the reader. Anything you write in
here is said to the reader.

Then, we create two dictionaries. The first represents \emph{items} that can be picked up and the
second represents directions the reader can move in this scene. The values of this dictionary are
the names of other functions representing scenes in the story.

Finally, at the end of the scene, we call the \code{interact} function.

When this scene is presented to the reader, the reader will first be told the story from the \code{say}
functions. Then, the reader will be asked to enter an instruction like \code{take <item name>} or
\code{go <direction>}. If these directions exist, then the named scene will be the next scene
called.

\section{Conclusion}

Data is more than just numbers and strings. \term{Lists} help us organize data by
order. \term{Dictionaries} help us organize data by meaning. Together, they let us build rich little
worlds out of simple parts.  They can contain not only numbers and strings, but also other lists and
dictionaries. In fact, lists and dictionaries can both contain themselves!

All data in a computer is stored as a number, even strings. Standards written by international
bodies mean that individual letters and characters have a set mapping between them and the numbers
that represent them. Lists and dictionaries, however, do not.

Python represents lists and dictionaries using numbers called \code{id}s that it keeps track of
internally. Instead of literally stuffing one list inside another, Python stores a number that
\emph{points} to the other list. This can lead to some confusing situations, but it's still an
example of computers following rules exactly.

Using lists and dictionaries, we can build a model world that we can explore as an interactive
story.

\item \textcolor{TermSage}{\bfseries\sffamily Curious: What Is Really Stored?}
Create a list and assign it to two different names:
\begin{lstlisting}
a = [1, 2, 3]
b = a
\end{lstlisting}
Now change \code{a[0] = 3.}.
\begin{enumerate}
  \item What happens to \code{b}?
  \item Why do you think this happens?
\end{enumerate}

\item \textcolor{TermSage}{\bfseries\sffamily A List That Contains Itself (Challenge).}\hint{We did this one in class.}
